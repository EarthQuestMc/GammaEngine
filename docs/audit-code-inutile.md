# Audit du code inutile

Conventions : `E/` = `eclipse/cauldron/src/main/java/` ; `S/` = `src/main/java/` ; `P/` = `patches/`. Constats lus dans le code et dans `run/` (configs générées par un serveur de test sans mod) ; **aucun coût n'a été chronométré**, les colonnes « coût » décrivent la nature du travail, pas sa durée. Les interrupteurs proposés sont des noms suggérés à placer dans `gammaengine.yml` ; aucun n'existe aujourd'hui. Cet audit prépare la phase 2 de la [feuille de route](roadmap.md).

## Détail

**Snooper.** `PlayerUsageSnooper` (`E/net/minecraft/profiler/PlayerUsageSnooper.java:21,28,39,81`) : `Timer("Snooper Timer", true)`, URL `http://snoop.minecraft.net/server?version=2`, période `900000L` ms, envoi par `HttpUtil.func_151226_a` (ligne 78). Activation : `isSnooperEnabled()` lit `snooper-enabled`, défaut `true` (`E/net/minecraft/server/dedicated/DedicatedServer.java:483-486`) ; `run/server.properties:21` vaut `true`. Démarrage au tick 100 (`E/net/minecraft/server/MinecraftServer.java:891-895`, ligne marquée Spigot), statistiques mémoire tous les 6000 ticks (`:898-900`). `MinecraftServer` implémente `IPlayerUsage` (`E/net/minecraft/profiler/IPlayerUsage.java:5-9`) : un mod peut référencer ces types, donc **coquille** : `startSnooper()` sans effet et `isSnooperEnabled()` fixé à faux, interrupteur proposé `gamma_legacy_snooper`.

**Auto-updater CraftBukkit.** `S/org/bukkit/craftbukkit/v1_7_R4/updater/{AutoUpdater,BukkitDLUpdaterService,ArtifactDetails}.java`. `CraftServer.java:249-254` : `updater.setEnabled(false); // Spigot` puis `check()`, qui retourne immédiatement (`AutoUpdater.java:72`, `if (!isEnabled()) return;`) : ni fil ni réseau. `bukkit.yml` : `auto-updater.enabled: false` (`src/main/resources/configurations/bukkit.yml:41-42`, `run/bukkit.yml:41-42`). L'avertissement aux joueurs (`CraftServer.java:1531`) ne s'exécute donc pas. Rien à faire.

**Vérification de version Forge.** `ForgeVersion.startVersionCheck` (`E/net/minecraftforge/common/ForgeVersion.java:71-73`) ne fait plus de requête : `status = UP_TO_DATE; // Crucible`. Appel conditionné par `ForgeModContainer.disableVersionCheck` (`E/net/minecraftforge/common/ForgeModContainer.java:281-284`). `ForgeVersion` est une API publique que des mods interrogent (`getStatus`, par exemple `E/net/minecraftforge/client/ForgeHooksClient.java:434`) : garder la classe. Autres accès réseau trouvés (motif `new URL(` / `openConnection`) : `LibraryManager` (téléchargement seulement si une bibliothèque manque, `CrucibleServerMainHook.java:68-71`), `MojangNameLookup` (recherche de noms à l'usage), `TimingsExport` (uniquement sur `/timings paste`), `BukkitDLUpdaterService` (inatteignable, voir plus haut), `E/Start.java:85-87` (lanceur de développement de l'arbre Eclipse ; non vérifié s'il est empaqueté). Aucune vérification de version propre à Crucible ni à GammaEngine : le commentaire de `ForgeVersion.java:73` suggère d'en réutiliser le point d'entrée.

**Métriques.** (a) MCStats : `S/org/spigotmc/Metrics.java:62` (`BASE_URL = "http://mcstats.org"`), `Timer("Spigot Metrics Thread", true)` ligne 229, démarré sans condition dans `SpigotConfig.registerCommands()` (`S/org/spigotmc/SpigotConfig.java:78-85`), appelé à `DedicatedServer.java:267`. Désactivation utilisateur : `opt-out` dans `plugins/PluginMetrics/config.yml` (`run/plugins/PluginMetrics/config.yml` : `opt-out: false`). (b) bStats : copie de la bibliothèque dans `S/io/github/crucible/Metrics.java` (URL ligne 36, `Timer(true)` ligne 220, envoi sur le fil principal ligne 228), instanciée à chaque démarrage par `CrucibleModContainer.serverStarting` avec l'identifiant **6555, celui du projet Crucible** (`S/io/github/crucible/CrucibleModContainer.java:95`) ; `run/plugins/bStats/config.yml` : `enabled: true`. Conséquence : un serveur GammaEngine envoie des statistiques sous l'identité d'un autre projet, sans demande. Neutralisation : ne pas appeler `start()` ni construire `Metrics`, garder les classes (`CrucibleModContainer.metrics` est un champ public statique, ligne 40 ; aucun autre usage trouvé dans `S/` ni `E/`). Interrupteur proposé : `gamma_legacy_metrics`. Les deux dossiers de `run/plugins/` (`PluginMetrics`, `bStats`) viennent de ces deux services, pas de plugins.

**Interface Swing.** `E/net/minecraft/server/gui/{MinecraftServerGui,PlayerListComponent,StatsComponent,IUpdatePlayerListBox}.java`. Création : `MinecraftServer.main` parcourt les arguments, `nogui` / `--nogui` met le drapeau à faux (`MinecraftServer.java:1658`), puis `if (flag && !GraphicsEnvironment.isHeadless()) dedicatedserver.setGuiEnabled()` (`:1735-1737`) → `MinecraftServerGui.createServerGui` (`DedicatedServer.java:551-553`). **Actif par défaut sur une machine avec écran** (poste Windows), inactif sur serveur sans affichage. Aucun mod n'a de raison de référencer ces classes ; coquille malgré tout. Proposition : GUI seulement sur argument explicite, ou `-Djava.awt.headless=true` dans le futur script de lancement (aucun script n'existe).

**Mode démo.** `E/net/minecraft/world/demo/{DemoWorldServer,DemoWorldManager}.java` ; seul usage serveur : `MinecraftServer.java:372` (`isDemo() ? new DemoWorldServer…`), `isDemo` posé par `--demo` (`:1688`) ou l'option `demo` (`:2007`). Inactif, sans coût. Ne pas toucher.

**Convertisseurs.** `AnvilSaveConverter` (`E/net/minecraft/world/chunk/storage/AnvilSaveConverter.java`, 285 lignes) construit à `DedicatedServer.java:320` ; `isOldMapFormat` / `convertMapFormat` à `MinecraftServer.java:295-310` : lecture de `level.dat`, conversion seulement pour un format antérieur à Anvil. `PreYggdrasilConverter` (680 lignes) : `DedicatedServer.java:312` appelle `func_152714_a`, qui teste d'abord l'existence des anciens fichiers `.txt` (`PreYggdrasilConverter.java:525-539`) ; conversion avec requêtes Mojang seulement si ces fichiers existent (le reste de la méthode n'a pas été lu). Migrations de dossiers : `CauldronUtils.migrateWorlds` (`S/net/minecraftforge/cauldron/CauldronUtils.java:54-66`, appel `MinecraftServer.java:424`) : deux tests de dossier par monde, déplacement si l'ancien emplacement Cauldron existe. Peu coûteux sur un monde récent ; classes publiques qu'un outil ou un mod pourrait charger : coquille. Interrupteur proposé `gamma_legacy_converters`, gain faible.

**Ping legacy.** `E/net/minecraft/network/PingResponseHandler.java` est ajouté à chaque pipeline Netty (`E/net/minecraft/network/NetworkSystem.java:94`, nom `legacy_query`) ; il lit le premier octet (`:33`, test `== 254`), répond aux anciens pings, sinon se retire (`:100`). Coût négligeable. Les listes de serveurs et sondes de supervision anciennes émettent encore ce ping : garder.

**Restes de Cauldron et Thermos.** Présents : `S/thermos/` (`ThermosClassTransformer` = transformer KImagine qui corrige Climate Control, il est appelé pour chaque classe et ne teste que `asm.is(...)` ; `ThermosRemapper`, utilisé par les plugins ; `thermite/*` ; `wrapper/*` = cartes de chunks `ChunkBlockHashMap`, `LongHashMapTrove`, `ThermiteMap`, `VanillaChunkHashMap`, utilisées par `ChunkProviderServer`) ; `S/net/minecraftforge/cauldron/*` (`CauldronCommand`, `SushchestvoCommand`, `TileEntityCommand`, configurations `cauldron.yml`, `entities.yml`, `tileentities.yml`, `SushchestvoCache`, `TileEntityCache`, `VersionInfo`) ; attributs `Thermos-*` du manifeste (`build.gradle:161-168`) ; propriété `thermos.fastcraft.disable` (`E/cpw/mods/fml/relauncher/CoreModManager.java:366,399`). Tous actifs et partie intégrante du fonctionnement (cartes de chunks, remapping) : leur coût relève d'un autre passage ; interdit de les supprimer (références par des mods via `CauldronHooks`, `CraftServer`).

**Spawn chunks.** Deux effets distincts. (1) Au démarrage, `initialWorldChunkLoad` charge 25 × 25 = 625 chunks autour du spawn de la dimension 0 (boucle `-192..192` pas 16, `MinecraftServer.java:455-495`, `i * 100 / 625` ligne 483), précédés de `ChunkPrefetcher.prefetchSpawnRegion(worldserver, 192)` (`:472`) qui lit et décode en parallèle les chunks déjà générés (`S/io/github/gammaengine/world/ChunkPrefetcher.java:51`) ; les chunks à générer restent séquentiels. (2) Maintien en mémoire : `World.keepSpawnInMemory = false` par défaut (`E/net/minecraft/world/World.java:279`) ; `DimensionManager.shouldLoadSpawn` (`E/net/minecraftforge/common/DimensionManager.java:447-450`) n'est vrai que si un mod appelle `keepLoaded` (`:88`) ou si Bukkit pose `setKeepSpawnInMemory` (`S/org/bukkit/craftbukkit/v1_7_R4/CraftWorld.java:1270`), et alors `ChunkProviderServer.java:120` protège les chunks proches du spawn du déchargement. Le coût par tick du maintien est donc déjà nul par défaut ; reste le chargement de démarrage. Proposition : rayon de démarrage configurable (`gamma_startup_spawnRadiusChunks`, défaut à choisir après mesure), `loadChunkOnProvideRequest` laissé intact. Risque : un mod ou un plugin qui suppose le spawn chargé ; premier joueur plus lent à entrer.

**`MapGenStructureData`.** `E/net/minecraft/world/gen/structure/MapGenStructureData.java`, instancié par `MapGenStructure.java:245-255` (`perWorldStorage.loadData` ou `new`) ; `func_143026_a` appelle `markDirty()` (`:289-292`) à chaque nouveau départ de structure ; `WorldServer.saveLevel` exécute `mapStorage.saveAllData(); perWorldStorage.saveAllData();` (`E/net/minecraft/world/WorldServer.java:1116-1121`) : le NBT complet de chaque générateur de structures « sale » est réécrit sur le thread serveur à chaque sauvegarde. Le fichier est aussi relu au chargement. `perWorldStorage` contient d'autres `WorldSavedData` (villages, données de mods) : on ne peut pas sauter `saveAllData` globalement, seulement rendre `MapGenStructureData.markDirty` inopérant derrière un interrupteur (`gamma_structure_dataPersist`). Raison de la prudence : sans fichier, les départs de structure doivent être recalculés par `MapGenStructure` depuis la graine pour les chunks voisins générés ensuite ; un générateur de mod non déterministe (`Random` non dérivé de la graine) perdrait la cohérence entre sessions. Cette analyse vient de la lecture de `MapGenStructure`, non d'un essai : à valider par génération comparée sur graine fixe.

**Profiler vanilla.** `E/net/minecraft/profiler/Profiler.java:19` `public boolean profilingEnabled` (faux) ; `startSection` et `endSection` sortent immédiatement (`:31-33`, `:46-48`). Seul interrupteur : `/debug start` (`E/net/minecraft/command/CommandDebug.java:54`). Les mods appellent `theProfiler.startSection` partout (type massivement référencé) : garder tel quel tant que le coût n'est pas mesuré. Le profileur GammaEngine est séparé (`S/io/github/gammaengine/profiler/`, `gamma_profiling_enabledAtStartup=false`, `GammaConfig.java:45`).

**Timings.** v1 : `S/org/spigotmc/CustomTimingsHandler.java` est déjà une façade qui crée un `Timing` v2 « (Deprecated API) nom » (`:86-97`, `:138-149`). v2 : `S/co/aikar/timings/` (19 classes), `Timings.timingsEnabled = false` (`Timings.java:43`), activable au démarrage par `timings_enabledSinceServerStartup` (défaut `false`, `S/io/github/crucible/CrucibleConfigs.java:190`, lu à `CrucibleModContainer.java:282`) ou à chaud par `/timings on` (`co/aikar/timings/TimingsCommand.java:111`). Désactivé, `TimedEventExecutor.execute` court-circuite (`TimedEventExecutor.java:75`), mais **le constructeur crée un `Timing` par méthode d'écouteur** à l'enregistrement (`:69`) et les `MinecraftTimings.*.startTiming()` restent dans la boucle de tick (`MinecraftServer.java:495,923`). Proposition : création paresseuse du `Timing` au premier passage activé. Risque faible.

**RCON et Query.** `DedicatedServer.java:372-383` : démarrés seulement si `enable-query` / `enable-rcon` sont vrais ; défaut faux (`run/server.properties:7,12`). Aucun fil créé sinon. Rien à faire.

**Aide Bukkit.** `S/org/bukkit/craftbukkit/v1_7_R4/help/SimpleHelpMap.java` : `clear()`, `initializeGeneralTopics()` (lit `help.yml`) à `CraftServer.enablePlugins(STARTUP)` (`CraftServer.java:333-335`), puis `initializeCommands()` à POSTWORLD (`:352`) ; méthodes `synchronized` (`SimpleHelpMap.java:66,77,98`). **Ebean.** `E/org/bukkit/plugin/java/JavaPlugin.java:345` : `if (description.isDatabaseEnabled())` seulement ; `CraftServer.configureDbConfig` (`CraftServer.java:1067-1075`) n'est appelé que dans ce cas. Les jars `org.avaje:ebean:2.7.3`, `sqlite-jdbc`, `mysql-connector-java`, `persistence-api` (`build.gradle:127-130`) ne pèsent que sur le hachage de démarrage (environ 2 + 4 + 1 Mo dans `run/libraries`). ## À ne pas toucher (fonctionnement constaté)

- **Statistiques et succès.** `ServerConfigurationManager.writePlayerData` écrit le NBT du joueur puis `StatisticsFile.func_150883_b()` (`E/net/minecraft/server/management/ServerConfigurationManager.java:349-358`), sur le thread serveur, à la déconnexion et lors des sauvegardes de joueurs (appelants de `writePlayerData` : non tracés). `StatisticsFile.func_150876_a` (`E/net/minecraft/stats/StatisticsFile.java:211`) pousse les mises à jour au client. Fonction visible des joueurs : ne pas désactiver ; seule l'écriture asynchrone serait un sujet de performance, à mesurer.
- **Remapping des plugins.** Paresseux, par classe, au `defineClass` du `PluginClassLoader` : détail dans [chargement.md](carte/chargement.md) (sections « Classes et méthodes clés » et « Pièges »).
- **Commandes.** Vanille : `CraftServer.setVanillaCommands` (POSTWORLD, `CraftServer.java:348,360`) ; Forge : `FMLServerStartingEvent.registerServerCommand` (`CrucibleModContainer.java:92-93`) ; Bukkit et Spigot : `SpigotConfig.registerCommands` (`SpigotConfig.java:73-76`) et `commands.yml`. Coût de démarrage, pas de tick.
- **`MapStorage` général** (villages, scoreboard, données de mods) : voir `MapGenStructureData`.

## Non demandé, à discuter

1. **Hachage MD5 d'environ 103 Mo à chaque démarrage** (`du run/libraries` : 103 Mo, dont `org/scala-lang` 28 Mo, `com/typesafe` 3 Mo, `org/xerial` 4 Mo) : `LibraryManager.checkOne` (`S/io/github/crucible/bootstrap/LibraryManager.java:230-250`). Déjà parallélisé ; un contrôle taille + date de modification mémorisé éviterait la relecture. L'utilité de Scala dépend des mods (non vérifié).
2. **Trois passes ASM par classe chargée** avant les transformers de FML : `LwjglRedirectTransformer` (`ClassReader` + `ClassWriter(0)`, `S/me/eigenraven/lwjgl3ify/core/LwjglRedirectTransformer.java:34-47`), `UnfinalizeObjectHoldersTransformer` (`ClassNode`), et `ImagineASMClassTransformer` de KImagine (arbre `ImagineASM` pour chaque classe, jar `run/libraries/pw/prok/KImagine/0.2.0`). Non vérifié si KImagine saute `build()` quand rien n'a changé. Candidat à une fusion ou à un pré-filtre par recherche de chaînes dans le pool de constantes.
3. **`javax/servlet/` réécrit en `jakarta/servlet/`** par `LwjglRedirectTransformer.java:54-58` alors que seule `javax.servlet-api:4.0.1` est fournie (`build.gradle:93`) : `NoClassDefFoundError` possible pour un mod ou un plugin qui utilise Servlet ou Jetty. Non reproduit.
4. **`FMLSecurityManager.defman` peut être nul** : `FMLTweaker.java:36` fait `sm.defman = System.getSecurityManager()` (nul avec `-Djava.security.manager=allow`, `java9args.txt:2`), alors que le patch appelle `defman.checkPermission(perm)` pour les permissions nommées `register` (`P/cpw/mods/fml/relauncher/FMLSecurityManager.java.patch`). NPE possible si une telle permission est demandée. Non reproduit.
5. **Expression régulière par appel** : `name.replaceAll("\\.", "\\/")` dans `PluginClassLoader.findClass` pour les noms `net.minecraft.` (`E/org/bukkit/plugin/java/PluginClassLoader.java:388`).
6. **Carte d'héritage globale non synchronisée** : `JavaPluginLoader.getGlobalInheritanceMap` initialise un champ sans verrou (`E/org/bukkit/plugin/java/JavaPluginLoader.java:410-440`) ; piège si le chargement des plugins devient parallèle.
7. **Vie privée et marque** : deux services de télémétrie actifs sans consentement (MCStats et bStats sous l'id Crucible 6555).
8. **Code mort dans `JavaPluginLoader`** : branche `if (false)` qui garde `TimedRegisteredListener` (`E/org/bukkit/plugin/java/JavaPluginLoader.java:338-340`).
